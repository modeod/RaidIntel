# Правила для XML в RimWorld

Патчи применяются к склеенному дереву всех модов **после** сборки, но **до**
`XmlInheritance.Resolve()` — значит патчить можно и абстрактные шаблоны.

**IMPORTANT: если xpath ничего не нашёл, ошибки НЕ будет — патч тихо не сработает.**
Проверять результатом: `Log.Message` в конструкторе своего узла. Есть строка в логе —
патч применился, виновата логика. Нет строки — виноват xpath.

## Операции

| Нужно | Операция |
|---|---|
| встать выше по приоритету | `PatchOperationInsert` — вставляет **перед** узлом из xpath |
| добавить в конец списка | `PatchOperationAdd` (или `<order>Prepend</order>` в начало) |
| поменять одно значение | `PatchOperationReplace` |
| подменить класс узла, сохранив его поля | `PatchOperationAttributeSet` |
| совместимость с другим модом | `PatchOperationFindMod` |

## Ловушки

- Предикаты в xpath применяются слева направо: `li[@Class="X"][1]` — первый среди тех,
  у кого этот Class. В `DutyDef AssaultColony` узлов `JobGiver_AITrashBuildingsDistant`
  **два** — без `[1]` патч сработает дважды.
- `DutyDef.thinkNode` существует в **одном экземпляре на всю игру** и делится между
  всеми пешками всех рейдов. Правка там — глобальная. Что должно отличаться от рейда
  к рейду, идёт через поля `PawnDuty` или через свои узлы, читающие ситуацию в рантайме.
- Списки при наследовании (`ParentName`) заменяются целиком, не сливаются.
- Ванильные теги вставки поддеревьев: `Humanlike_PreMain`, `Humanlike_PostMain`,
  `Humanlike_PostDuty`, `Humanlike_PostMentalState`.
