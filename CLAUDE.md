# RaidIntel — контекст проекта для Claude Code

Мод для RimWorld **1.6**. Учебный шаг к большому проекту "Custom raider AI".

## Жёсткие технические факты (не выдумывать и не менять)

- Платформа: Unity 2022.3.35f1, Mono, **TargetFramework = net472**.
  НЕ net8.0, НЕ netstandard2.0, НЕ .NET 3.5 (3.5 — это устаревшие туториалы, они врут).
- Ссылки на игру — только через NuGet `Krafs.Rimworld.Ref` (1.6.*).
  Не добавлять прямые ссылки на Assembly-CSharp.dll.
- `Lib.Harmony` всегда с `ExcludeAssets="runtime"`.
- Синтаксис C# 11/12 компилируется, но BCL старый (Mono/net472):
  `record`, `init`, `Span<T>` требуют полифилов. По умолчанию их не использовать.
- Сборка кладётся в `1.6/Assemblies/`. Структура мода: `About/`, `1.6/{Assemblies,Defs}/`, `Source/`.

## Архитектурные правила проекта

- **`JobGiver` не патчить.** Два prefix'а на одном `TryGiveJob`, где первый вернул `false`,
  молча отменяют второй. Вместо этого — вставлять свой `ThinkNode` в think tree
  или подменять `DutyDef.thinkNode`.
- **Не патчить `PathFinder`** — в 1.6 он переписан на Unity Burst.
- **Время считать только через `Find.TickManager.TicksGame` или `TickInterval(int delta)`.**
  В 1.6 есть variable tick rate: объекты за кадром тикают реже, `counter++` врёт.
- **Многопоточность по умолчанию не вводить.** В 1.6 распараллелены только pathfinding
  и glow grid (через Burst). Весь AI — main thread. Офф-тред только после замера в
  Dubs Performance Analyzer.
- **Никаких ленивых кэшей "пересчитать при первом запросе"** — момент запроса зависит
  от положения камеры, это ломает детерминизм.
- Любой кэш обязан очищаться патчем на `MemoryUtility.ClearAllMapsAndWorld`.

## Правила ответов

- Каждое утверждение о конкретном API игры маркировать:
  ✅ проверено (путь к файлу/строка) · ⚠️ вывод · ❌ не проверено.
- Сигнатуры методов игры проверять в декомпиляторе Rider, а не по памяти.
