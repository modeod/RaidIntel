# Словарь RimWorld для бекендера

**Назначение:** перевод понятий RimWorld на язык, который уже есть в голове у веб/бекенд
C#-разработчика. Аналогии приблизительные по определению: они нужны, чтобы зацепиться.

**Легенда:** ✅ проверено · ⚠️ вывод/аналогия · ❌ не проверено

---

## 0. Главная смена парадигмы

| Твой мир | RimWorld |
|---|---|
| Процесс живёт между запросами, работа приходит извне | **Один вечный цикл.** Каждый тик игра сама обходит все объекты и спрашивает «что делаешь?» |
| DI-контейнер, конструкторы, интерфейсы | **Service locator через статику**: `Find.TickManager`, `Find.CurrentMap`, `DefDatabase<T>.GetNamed(...)`. DI-контейнера нет вообще |
| Запросы независимы, состояние в БД | **Всё состояние в памяти одного процесса** и целиком сериализуется в сейв |
| Масштабирование = больше инстансов | Масштабирования нет. Один поток, бюджет ~16 мс на кадр |
| Ошибка = 500 одному пользователю | Ошибка в тике = красная строка **каждый тик**, 60 раз в секунду, до конца игры |

⚠️ Отсюда главное правило производительности: убивает не сложность алгоритма,
а **частота вызова**. Метод на 50 строк раз в секунду дешевле метода на 3 строки,
вызываемого 60 раз в секунду для 200 пешек.

## 1. Данные и конфигурация

**`Def`** — XML в `Defs/`, который игра при старте превращает в C#-объект.
⚠️ Аналог: **`appsettings.json`, но строго типизированный, с наследованием (`ParentName`)
и кросс-ссылками**. Def — описание типа, не экземпляр: `ThingDef` «стальная стена» один
на всю игру, а стен тысячи. Def'ы read-only после старта и не сериализуются в сейв.

**`DefDatabase<T>`** — ⚠️ статический словарь `defName → объект`, реестр конфигураций.

**`DefOf`** — класс с полями, которые игра заполняет по имени поля.
⚠️ Аналог strongly-typed options: вместо магической строки — `JobDefOf.Goto`.
✅ Заполняется на шагах 10 и 12 из 14.

**`PatchOperation`** — XPath-операция над деревом конфигов всех модов.
⚠️ Аналог JSON Patch. Применяется на шаге 6, **до** превращения XML в объекты.
Единственный способ поменять чужой Def, не форкая чужой мод.

## 2. Доменные объекты

| Термин | Что это | Аналогия ⚠️ |
|---|---|---|
| `Thing` | всё на карте: предмет, стена, труп, пешка | базовый класс доменной сущности |
| `Pawn` | `Thing`, который живой и думает | агрегат с кучей под-трекеров |
| `Map` | одна карта: сетки, регионы, Things, погода | контекст/unit of work на всю симуляцию |
| `IntVec3` | целочисленная координата клетки | `struct` для ключа |
| `Hediff` | рана, болезнь, имплант, наркотик | эффект с временем жизни |

Внутри `Pawn`: `pawn.jobs`, `pawn.mindState`, `pawn.health`, `pawn.equipment`, `pawn.stances`.
⚠️ Агрегат, разбитый на под-сервисы.

**`ThingComp`** — кусок поведения, навешиваемый на `ThingDef` через XML.
⚠️ Прямой аналог **компонента ECS**: не «класс Дверь-С-Автозакрытием», а «Дверь + CompAutoClose».
Наследоваться от `Building_Door` — путь к конфликту, навесить Comp — нет.
`CompProperties` — конфиг из XML, `ThingComp` — рантайм-объект.

## 3. Время

| Термин | Что это |
|---|---|
| **tick** | один шаг симуляции. При 1x — 60 в секунду ✅ |
| `TickerType.Rare` | каждые **250** тиков (~4.2 с) ✅ |
| `TickerType.Long` | каждые **2000** тиков (~33 с) ✅ |
| `Find.TickManager.TicksGame` | единственный честный источник времени |
| `IsHashIntervalTick(N)` | «раз в N тиков, но не одновременно со всеми» ✅ |

Скорости: пауза 0, 1x=1, 2x=3, 3x=6, dev=15 тиков за кадр ✅.
⚠️ **Тик — единица работы, а не времени.**

`IsHashIntervalTick`: `(TicksGame + ID объекта) % N == 0`. Смысл не «реже», а
**размазать нагрузку**. ⚠️ Аналог jitter при ретраях.

**Новое в 1.6:** `TickInterval(int delta)` ✅ — игра может вызвать реже и передать,
сколько тиков пропущено. `counter++` больше не считает время.

## 4. Как пешка решает, что делать

Ядро проекта. Снизу вверх:

```
Job          ← "иди в клетку (12,0,45)"        = команда/DTO
JobDriver    ← как её исполнять, по шагам      = конечный автомат (Toil'ы)
JobGiver     ← кто эту команду выдал           = обработчик, вернул команду или null
ThinkTree    ← дерево из JobGiver'ов           = chain of responsibility
Duty         ← роль пешки в группе             = какое поддерево ей подключить
Lord         ← мозг всей группы                = оркестратор/сага
```

| Термин | Аналогия ⚠️ |
|---|---|
| `Job` | команда (Command), immutable-ish DTO |
| `JobDriver` | конечный автомат / шаги пайплайна |
| `Toil` | state в FSM |
| `ThinkNode_JobGiver` | обработчик, который либо ответил, либо пропустил дальше |
| `ThinkTree` | конфигурируемый пайплайн обработчиков |
| `DutyDef` | стратегия, подставляемая в пайплайн |
| `Lord` | оркестратор / сага-координатор |
| `LordJob` | определение саги |
| `LordToil` | состояние саги |
| `Trigger` | guard на переходе FSM |
| `Verb` | стратегия применения действия |

**Как это работает вживую (рейд):**

1. `IncidentWorker_RaidEnemy` выбирает `RaidStrategyDef` и `PawnsArrivalModeDef`.
2. Стратегия создаёт `LordJob`. Тот стартует в `LordToil` «собраться».
3. `LordToil.UpdateAllDuties()` каждому рейдеру выдаёт `Duty`.
4. `Duty` подключает своё поддерево в `ThinkTree` пешки.
5. Дерево обходится сверху вниз, пока `JobGiver` не вернёт `Job`.
6. `JobDriver` исполняет её по шагам.
7. Сработал `Trigger` — `LordJob` переключает фазу, роли меняются у всех разом.

⚠️ **Вот почему нельзя патчить `JobGiver`:** дерево останавливается на первом, кто ответил.
Два prefix'а на один `TryGiveJob`, где первый вернул `false` — второй молча не выполнится.
Правильно — **добавить свой узел в дерево**.

## 5. Как влезть в чужой код

**Harmony** — рантайм-перехват методов.
⚠️ Аналог: **middleware / interceptor / АОП**, применяемый к чужой сборке без точек расширения.

| Тип патча | Когда | Аналог ⚠️ |
|---|---|---|
| `Prefix` | до оригинала; `false` **отменяет** его | middleware, который может не вызвать `next()` |
| `Postfix` | после; видит и меняет результат | обработчик ответа |
| `Transpiler` | переписывает IL | правка байт-кода. Больно |
| `Finalizer` | ловит исключения | `try/finally` вокруг чужого кода |

**Правило по умолчанию: Postfix.** `Prefix` с `return false` выключает чужой метод
для всех модов сразу.

**`AccessTools`** — обёртка над рефлексией для private-полей.
⚠️ Дорого в горячем коде: результат кэшировать в `static readonly`.
Альтернатива — `Krafs.Publicizer`: делает private public на этапе компиляции ✅.

**`Assembly-CSharp.dll`** — вся игра одна сборка. Основной источник документации —
не вики, а Ctrl+Click в Rider.

## 6. Инфраструктура мода

| Термин | Что это |
|---|---|
| `packageId` | глобально уникальный ID, `Author.ModName`. **Менять после релиза больно** |
| `About.xml` | манифест: имя, версии, зависимости, порядок загрузки |
| `LoadFolders.xml` | `IfModActive="..."` — **мягкая зависимость без единой строки кода** |
| `Mod` (класс) | точка входа. Создаётся на шаге 3 из 14, **до** любого XML |
| `ModSettings` | настройки мода |
| `[StaticConstructorOnStartup]` | шаг 14, когда все Def'ы готовы |
| `Scribe` | сериализация. Одна функция пишет и читает, направление из `Scribe.mode` ⚠️ |

⚠️ **Ключевая ловушка порядка старта:** в конструкторе `Mod` Harmony ставить можно,
читать `DefDatabase` — нельзя, Def'ов ещё нет.
