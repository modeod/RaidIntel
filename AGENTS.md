# PREXIS — мод на ИИ рейдеров для RimWorld 1.6

Общий файл инструкций для всех агентов (Claude Code читает его через `@AGENTS.md`
из `CLAUDE.md`; Codex читает напрямую).

C# + XML Defs. Отладочный оверлей Raid Intel (подсистема диагностики) работает; цель — групповой тактический ИИ.
Разработчик — бывший C#-бекендер (веб), в Unity и геймдеве новичок.
Незнакомые игровые сущности объясняй, не считай известными.

## Сборка

```
dotnet build Source/Prexis/Prexis.csproj
```

DLL уезжает в `1.6/Assemblies/Prexis.dll`.

**IMPORTANT: exit code сборки — единственная автоматическая проверка в проекте.**
Запустить игру и увидеть поведение может только человек. Собирай перед тем, как сказать
«сделано», и никогда не выдавай несобранный код за готовый.

## Как искать

Сначала `rg` по символу, потом чтение нужного куска — не читай файлы целиком.
Связи в RimWorld идут через **строковые** `defName`, а не через типы, поэтому поиск
по строке находит быстрее, чем обход по ссылкам.

Ванильные Defs: `D:\Games\Steam\steamapps\common\RimWorld\Data\Core\Defs\` — обычный XML.
Декомпилированные исходники 1.6 — локальный клон, путь ниже в разделе «Идентификаторы».

## Факты о платформе, которые нельзя вывести из кода

| Факт | Почему так |
|---|---|
| `TargetFramework` = **net472**, рантайм Mono | C# 11/12 компилируется, но BCL старый: `record`, `init`, `Span<T>` требуют полифилов |
| Ссылки на игру — только NuGet `Krafs.Rimworld.Ref` | прямые ссылки на `Assembly-CSharp.dll` ломают сборку на чужой машине |
| `Lib.Harmony` всегда с `ExcludeAssets="runtime"` | иначе `0Harmony.dll` попадёт в мод и подерётся с модом Harmony |
| `[BurstCompile]` в моде — **no-op** | Burst в релизном билде только AOT |
| XML-патч нельзя выключить настройкой мода | `PatchOperation` идёт на шаге 6 из 14, задолго до настроек. Узел вставляет XML, решение принимает C# |

## Правила, которые дорого нарушить

Каждое правило — с причиной. Если причина перестала быть верной, правило надо удалить,
а не обходить.

1. **Не патчить `JobGiver.TryGiveJob` через Harmony.** Два prefix'а, где первый вернул
   `false`, молча отменяют второй. Вместо этого — свой `ThinkNode` через
   `PatchOperationInsert` в `DutyDef`.
2. **Не переписывать `PathFinder`.** В 1.6 он на Burst и из мода недоступен. Влиять
   через данные: `IPathFinderDataSource` и `IPathGridCustomizer`.
3. **Не вешать состояние рейда на `lord.loadID`.** Один инцидент создаёт до четырёх
   `Lord`; они умирают поодиночке и досоздаются. Носитель идентичности — множество
   пешек и собственный `raidId`.
4. **Время — только `Find.TickManager.TicksGame` или `TickInterval(int delta)`.**
   В 1.6 переменная частота тика: вне камеры объект тикает в 15 раз реже.
5. **Никаких ленивых кэшей «пересчитать при первом обращении».** Момент первого
   обращения зависит от камеры — недетерминированно, ломает Multiplayer.
6. **Любой кэш чистить самому** патчем на `MemoryUtility.ClearAllMapsAndWorld`.
   Статический кэш со ссылкой на `Map` или `Pawn` переживёт выход в меню и утечёт.
7. **Не делать `Unpatch` чужих патчей.** Так поступил Smarter Raider AI с Combat
   Extended и сломал CE всем остальным.
8. **Своих потоков не заводить.** Есть `Gilzoide.ManagedJobs.ManagedJobParallelFor`
   внутри `Assembly-CSharp`.

Там сгенерированное и бинарники; grep по ним — потраченное время и контекст.

(клон Chillu1/RimWorldDecompiled). Это справочник, не часть проекта — не редактировать.

## Проверка, что мод жив

После сборки и запуска игры в dev-консоли должна появиться строка:

```
[Prexis] Mod ctor done, Harmony patches applied.
```

Её нет — мод не загрузился (чаще всего: не собран DLL, или мод выключен в списке модов).
⚠️ Запустить игру и увидеть это может **только человек**.

## Маркировка достоверности — обязательна

**IMPORTANT: немаркированное утверждение читается как проверенное. Это главная ловушка проекта.**

✅ проверено по исходнику, с путём и строкой · 📣 дословная цитата игрока или автора ·
⚠️ логический вывод · ❌ не проверено

Сигнатуры методов игры проверять в исходниках, а не по памяти. В проекте уже дважды
всплывали классы, которых в 1.6 не существует (`Faction.TacticalMemory`, `TrapUtility`).

## Как со мной работать

- **Выносишь решение — назови допущение, на котором оно стоит.**
- **Не вычёркивай из скоупа молча.** Формат: проблема → во что результирует → варианты →
  что проверить. Не «мы этого не делаем».
- **Продуктовые решения принимает разработчик.** Инженерная дороговизна — вход в разговор,
  а не приговор фиче.
